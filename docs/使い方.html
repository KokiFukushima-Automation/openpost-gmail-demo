openpost 使い方

送信したメールの開封シグナルとクリックを確認するツールです。

画像の取得は本文の読了を証明しません。開封シグナルがなくても未読とは断定できません。

1. ローカルで操作を試す

プロジェクトで npm ci の後、npm run demo を実行し、デモ管理画面を開きます。架空データだけのデモです。外部へメールは届きません。終了するとデモのDBは消えます。

上の Compose から宛先・件名・本文を入力して Send。dryrun の表示はファイル生成のみです。実送信時は、設定した送信方式が表示されます。

2. 実際のメールを追跡する（常駐版）

サーバーの公開HTTPS URL、SQLiteを保存する永続領域、送信元Gmailの認証を先に設定します。詳しくは 配置手順とREADMEを参照。個別設定が済んでいなければ実送信はできません。

管理画面のComposeで自分のテスト受信先へ送信し、受信メールの画像を表示。管理画面のメッセージ一覧から該当件名を開き、開封数とイベント詳細を確認します。送信直後の先読みと人が開いた時刻を分けて判断してください。

クラウド版で使える範囲

今回配置したクラウド版は追跡・Gmail連携専用です。管理画面からは送信しません。Gmail連携の送信前track・送信後linkで登録したメールだけを追跡します。Gmail用add-onは addon/ のソースとREADMEに導入手順があります。Chrome拡張だけではGmail作成画面にピクセルは入りません。

PC版Gmailのアドオンから実送信・受信・照合を確認済みです。宛先を確定→封筒アイコンの Track with openpost→必要なら管理画面用の件名を入力→追跡画像を挿入を1回→Gmailの送信。挿入後は宛先を変更しないでください。送信後は5分ごとの照合を待ちます。カードの読み込みエラーはカード内の「更新」で再読み込みしてください。独自OAuth/SMTPとスマホ作成画面は未検証です。管理画面の Refresh で最新状態を取得します。Cloud Run上の通知・予約・定期ジョブは動作しません。送信済みの照合だけは本人のApps Scriptで5分ごとに動きます。

アプリとして開く（PWA）

HTTPSの管理画面にログインし、Chromeメニューの「キャスト、保存、共有」などにあるインストール項目を選びます。Chromeのバージョンで名称が変わる場合があります。iPhoneではSafariの共有から「ホーム画面に追加」。ブラウザ上で動く管理画面を独立したウィンドウにする方式で、App Store配布版ではありません。端末ごとのインストール操作は未検証です。オフラインでは最新の開封状況を取得できません。

3. Gmailの一覧に表示する

Chromeの chrome://extensions →デベロッパーモード→「パッケージ化されていない拡張機能を読み込む」で extension/ を選びます。インストールや権限の確認は画面の内容を確認して行ってください。

拡張のオプションにご自身のサーバーURLとAPI_TOKENを入力し「接続して保存」。Gmailを再読み込みします。IDが一致した追跡済みメールにだけ記号が出ます。詳細は拡張の設定手順へ。

トークンは通常ブラウザを閉じると消えます。保存を明示的に選ぶと端末に残ります。接続を解除するにはオプションの「接続を解除」。

4. 記号の読み方

表示意味
○開封シグナルなし。未読とは断定しません
◐自動先読みの可能性。本人の開封は未確認
●開封の可能性あり
◉複数のシグナルによる推定。読了の保証ではありません
↩返信あり

スレッドの記号は宛先全員の既読を意味しません。複数宛先に一通で送信する形式では、誰が開いたかを特定できません。

開封を判断する際の制限

下書き・送信済み未照合の画像取得は開封数に含めません。Google経由の送信直後60秒以内の取得も先読みとして扱うため、人が早く開いても◐のままの場合があります。画像のキャッシュや拒否による取りこぼし、送信済みコピーを自分で開いた際の混入もあり得ます。○や◐を「相手が未読」と判断しないでください。複数宛先では個人別の開封も判定できません。

表示されない場合

まずオプションの接続結果を確認し、Gmailを再読み込みしてください。未追跡のメール、スレッドIDの登録がないメール、Gmailの画面構造変更は表示対象外です。認証失効や通信失敗時は古い記号を消します。組織ポリシーで拡張が禁止されている場合、回避せず管理者に確認してください。
