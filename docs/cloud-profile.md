# Cloud Run用の追跡・Gmail連携プロファイル

フル機能の常駐版（`openpost serve`）とは別に、`Dockerfile.cloud` から
`dist/cloud/index.js` を起動する、少量利用向けのプロファイルです。

## この構成で提供するもの

- 追跡ピクセル、リンク、オプトアウト、管理画面、Bearer API、Gmail add-onのtrack/link。
- SQLiteはコンテナのディスクへ永続保存しません。リクエストごとに非公開GCSの圧縮スナップショットから復元し、書き込み後は保存完了を待ってから応答します。
- GCSの世代番号を条件にしたロック・保存・解除により、別プロセスの更新を上書きしません。
- 正常応答前に保存できなかった場合は500/503。失敗を開封成功として返しません。
- 暗号鍵・API_TOKEN・管理画面パスワードはデプロイ設定。公開記事やビルドソースに含めません。
- 専用サービスアカウントに専用バケットのオブジェクト権限のみ付与。バケットは非公開。

## フル版との違い（省略せず説明すること）

このプロファイルは **追跡・Gmail連携専用** です。メールの実送信はGmail側で行い、
送信前の `/api/addon/track` と、送信後の `/api/addon/link` で対応付けます。
Gmail connectorで送る試験は、そのconnectorを経由した経路の検証であり、
フル版の独自OAuth/SMTPトランスポートの実証ではありません。2026-10-19にはPC Chromeの通常Gmailアドオン経路でも実送信・受信・画像保持・Apps Scriptの実照合を確認しました。

- クラウド管理画面からの実送信・Composeは無効。
- 送信済み照合は本人のApps Script側の5分トリガー。未照合/下書きの取得は開封数に含めないため、照合前の早い開封は取りこぼす場合があります。Googleの先読み時間帯や画像キャッシュ、送信済みコピーの自己開封も判定に影響します。
- バックグラウンド通知、リマインダー、キャンペーン、返信ポーリング等の定期ジョブは動かしません。
- 常時SSE接続は無効で、管理画面はRefreshで更新。Chrome拡張は30秒間隔で状態を取得します。
- PWAを有効化。管理画面を独立ウィンドウ／ホーム画面から開けます。クラウド用manifestは送信・共有先を提供せず、開封管理だけに限定します。OSごとのインストール操作は未検証です。
- 生のSQLiteスナップショットは16MiBまで。この上限に近づく用途は永続ディスクを持つ常駐版へ移行してください。
- リクエストのロック有効期間は120秒。Cloud Runの応答期限は60秒で、送信処理のない短時間APIだけを動かします。プロセス終了時にロックが残る場合、最大120秒は503となる場合があります。
- API_TOKENを失効しても、Gmail画面の既存記号が消えるのは次回更新時です。

## 無料枠と保存先

Cloud Runは最小インスタンス0、最大1、同時リクエスト1、リクエスト課金。
GCSは無料枠対象の米国リージョン、STANDARD、少量データ。
無料枠は請求アカウント全体で共有され、利用超過時の課金を自動で止める機能ではありません。
[Cloud Run料金](https://cloud.google.com/run/pricing) と
[Google Cloud無料枠](https://docs.cloud.google.com/free/docs/free-cloud-features) に従い、
実際の保存量・リクエスト数・既存サービスの消費を確認してください。

変更のない管理画面の閲覧でもロック作成のオペレーションは発生します。
大量配信・頻繁なダッシュボード更新を前提に無料と断定してはいけません。
既存サービスの設定や既存データには触れず、専用サービス／バケットへ分離します。

## 配置

1. `npm ci && npm run build && npm run lint && npm test`。
2. 非公開GCSバケットと、当該バケットだけにアクセスできるサービスアカウントを準備。
3. `.gcloudignore` で `.env*`、`cloud-local/`、DB、ログ、秘密鍵を除外。
4. `cloudbuild.openpost.yaml` と `Dockerfile.cloud` でイメージをビルド。
5. 専用Cloud Runサービスを上記上限で配置。API_TOKEN、DASHBOARD_PASSWORD、TRACKING_SECRETは十分に長いランダム値。
6. 確定したサービスURLへTRACKING_BASE_URLを更新。Gmailから届くのは認証なしのピクセル／リンクだけで、APIと管理画面には認証を要求。
7. 実GCSへの保存→別リクエストでの復元に加え、Cloud Runの別リビジョンへ更新しても状態が残ることを確認。

配置先と秘密情報は `cloud-local/` に0600で保存。これはgitとクラウドのソースアップロードから除外されます。
